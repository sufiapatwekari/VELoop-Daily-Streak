# VELoop Rewards — Daily Streak System

## 1. Project Overview

VELoop Rewards is a full-stack MERN application that provides a daily streak and reward system for users.

Users can register and log in, check their daily streak, claim rewards, view their VES wallet balance, and check their transaction and streak history.

The main focus of the project is to make the reward system secure and backend-controlled. The frontend only displays the data received from the backend. Streaks, reward eligibility, claim timing, wallet balance, and transaction records are controlled by the backend.

---

## 2. Project Objectives

The main objectives of the project are:

* Provide a user registration and login system.
* Allow users to maintain a daily streak.
* Provide rewards for each successful check-in.
* Prevent users from claiming rewards before the allowed time.
* Reset the streak when the user misses the allowed period.
* Maintain a VES wallet for users.
* Store wallet transactions and streak history.
* Provide a responsive and user-friendly React interface.
* Protect APIs using JWT authentication and rate limiting.
* Keep reward and streak information controlled by the backend.

## 6. Main Features

### User Authentication

Users can:

* Register an account.
* Log in using email and password.
* Access protected user information.
* View their profile.

Passwords are stored using hashing instead of plain text.

JWT is used for authentication.

### Daily Streak

Users can claim one daily reward according to the streak rules.

The system maintains:

* Current streak
* Longest streak
* Current reward day
* Total rewards
* Check-in status
* Next claim time

### Seven-Day Reward System

| Day   | Reward              |
| ----- | ------------------- |
| Day 1 | +5 VES              |
| Day 2 | +10 VES             |
| Day 3 | +15 VES             |
| Day 4 | ₹1 Amazon Gift Card |
| Day 5 | ₹2 Amazon Gift Card |
| Day 6 | +30 VES             |
| Day 7 | ₹5 Amazon Gift Card |

After completing the seven-day cycle, the reward cycle can continue according to the configured streak system.

---

## 7. Claim Rules

The backend controls the complete claim process.

Important rules include:

* A reward can be claimed only when the user is eligible.
* The normal claim interval is 24 hours.
* A user cannot claim the same reward twice.
* Rewards must be claimed in the correct sequence.
* The backend calculates the next claim time.
* The frontend cannot manually change the streak or reward amount.

The backend is the source of truth for the reward system.

---

## 8. Missed-Day Reset

The system uses a missed reset period of 48 hours.

If a user does not claim the expected reward within the allowed period, the streak can be reset.

This prevents users from keeping an old streak indefinitely without completing their daily check-ins.

The reset is handled by the backend.

---

## 9. VES Wallet

The application provides a VES wallet for rewards that are given as VES.

The wallet stores:

vesBalance


When a user receives a VES reward:

Previous VES Balance
        ↓
Reward Added
        ↓
New VES Balance


Example:

Balance Before: 0 VES
Day 1 Reward:   +5 VES
Balance After:   5 VES


Wallet changes are handled by the backend.

---

## 10. Transaction History

Every wallet reward transaction is recorded.

Transaction information includes details such as:

* User
* Reward amount
* Balance before
* Balance after
* Transaction source
* Date and time

The transaction history allows users to see how their VES balance was changed.

---

## 11. Streak History

The application stores the user's previous streak activity.

The history can contain information such as:

* Reward day
* Reward
* Claim status
* Claim date
* Cycle information

This provides a record of the user's reward activity.

---

## 12. Backend-Controlled Data

One of the important design principles of the project is:

> **The React frontend displays the data, but the backend controls the streak and rewards.**

The frontend does not hardcode:

* Current streak
* Reward status
* Wallet balance
* Claim time
* Reward eligibility

Instead, the frontend requests the latest information from the backend.

---

## 13. Timer and Claim Time

The backend provides:

* `serverTime`
* `nextClaimAt`

The frontend uses these values to display the countdown timer.

This prevents the user from changing their computer time to bypass the reward waiting period.

## 18. Backend Claim Flow

The reward claim process works approximately as follows:

User clicks "Claim"
        ↓
Frontend sends claim request
        ↓
Backend verifies JWT
        ↓
Backend finds user streak
        ↓
Checks claim timing
        ↓
Checks streak and reward eligibility
        ↓
Gets reward from database
        ↓
Updates wallet if reward is VES
        ↓
Updates streak
        ↓
Creates transaction record
        ↓
Creates streak history
        ↓
Creates audit log
        ↓
Returns updated data
        ↓
Frontend displays result

## 23. Project Rule

The most important rule of the system is:

> The backend is the source of truth.

This means the frontend cannot directly decide:

* which reward is available
* when the user can claim
* how much VES the user receives
* what the current streak is
* whether a reward has already been claimed

All important reward decisions are made by the backend.

## 24. Limitations

Current limitations include:

* Amazon Gift Card rewards are represented as configured reward records; actual gift-card delivery is not integrated.
* The project currently uses a local development setup for frontend and backend.
* Production deployment and HTTPS configuration would be required for real-world use.
* Additional monitoring and logging would be useful for a production environment.

## 26. Final Summary

VELoop Rewards is a MERN-based daily streak and reward application designed to provide users with a simple and controlled reward experience.

The project combines React for the frontend, Node.js and Express for the backend, and MongoDB for data storage.

The system provides authentication, daily streak tracking, seven-day rewards, VES wallet management, transaction history, streak history, claim timing, missed-day handling, and security controls.

The key design principle is that the backend controls all important streak and reward logic, while the frontend displays the information received from the backend.

This approach makes the system more reliable, secure, and suitable for further development into a production-ready reward platform.
